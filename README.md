# Project 11 — Visual Waste Sorting Assistant (Midterm AI Core)

This repository contains a **from-scratch PyTorch CNN** for classifying TrashNet images into six classes: `cardboard`, `glass`, `metal`, `paper`, `plastic`, and `trash`. The Midterm scope is the AI core: model construction, training, baselines, controlled ablations, learning-curve analysis, evaluation, and a live image-prediction demo.

All active model, training, evaluation, and demo code uses PyTorch. The package intentionally omits trained checkpoints and historical framework artifacts; the final PyTorch checkpoint and full-dataset metrics are generated by running the documented experiment pipeline.

## 3. Dataset preparation

The ZIP intentionally does not include the full TrashNet dataset. Read `data/LICENSE.md` before downloading.

```bash
python scripts/prepare_dataset.py                 # safe dry run
python scripts/prepare_dataset.py --confirm       # download and prepare full TrashNet
```

The script verifies the pinned archive SHA-256 by default, removes hidden files and AppleDouble entries such as `._cardboard9.jpg`, validates image bytes **before splitting**, creates deterministic 70/13/17 train/validation/test splits (seed 42), and writes `data/split_manifest.json`. Invalid or metadata files cannot influence split sizes or class counts.

The full dataset folders and downloaded archive are git-ignored and must not be included in a submission ZIP. The `data/sample/` images are synthetic and intended only for offline smoke tests; they are **not suitable for estimating real-world model performance**.

## 4. CNN architecture

The default network is trained from random initialization; it does not use transfer learning or pretrained solution weights.

```text
RGB image (64 x 64)
  -> Conv2d 3x3 -> BatchNorm2d -> ReLU -> MaxPool2d  (16 channels)
  -> Conv2d 3x3 -> BatchNorm2d -> ReLU -> MaxPool2d  (32 channels)
  -> Conv2d 3x3 -> BatchNorm2d -> ReLU -> MaxPool2d  (64 channels)
  -> Conv2d 3x3 -> BatchNorm2d -> ReLU -> MaxPool2d  (128 channels)
  -> Adaptive Global Average Pooling
  -> Dropout -> Dense(128) -> ReLU -> Dropout -> Dense(6 logits)
```

The model returns logits for `torch.nn.CrossEntropyLoss`. Softmax is applied only when probabilities are needed for predictions. The `build_model`, `train`, `predict`, `predict_proba`, and `load_trained_model` functions are implemented in `starter/student_core.py`.

## 5. Train and evaluate the Midterm experiments

With the dataset prepared:

```bash
python scripts/run_experiments.py --epochs 25 --seed 42
```

This runs a control CNN and one-factor-at-a-time variants for augmentation, dropout, depth and learning rate, plus `no_reg`. Use `--only base,aug_none --epochs 5` to run a smaller subset during development. `--force` ignores cached PyTorch results. A cache entry is reused only if its split fingerprint, seed, model configuration, image size, epoch budget and batch size match and its PyTorch checkpoint is present.

The training loop uses Adam, class-weighted cross-entropy based on **training labels only**, ReduceLROnPlateau on validation loss, deterministic evaluation transforms, and best-checkpoint restoration. Each experiment's best epoch is selected by minimum validation loss; the final configuration is selected by validation macro-F1 **among configurations with dropout > 0**, because the Midterm rubric requires dropout regularization. The `no_reg` and `drop_0.0` configurations remain ablations and cannot become the final demo model. The held-out test split is evaluated only after this selection, for the selected CNN and the two required baselines. Test metrics are not generated for every ablation configuration.

Outputs include:

- `results/run_<name>.json`: configuration, history, best epoch, validation metrics and provenance.
- `results/baselines.json`: majority-class and colour-histogram centroid baseline metrics.
- `results/summary.csv` and `results/summary.md`: validation metrics for ablations and test metrics only for the selected model/baselines.
- `results/figures/`: learning curves, ablation plots, selected model confusion matrix, and final test comparison.
- `models/waste_cnn.pth`: selected PyTorch checkpoint for the demo.

A bootstrap confidence interval over test images quantifies test-sample uncertainty only; it does not quantify variability across random initialization or training seeds. The project currently uses a single primary seed, so small configuration differences should be interpreted cautiously.

## 6. Offline smoke test

```bash
python scripts/run_experiments.py --quick
```

This runs a two-epoch smoke test using only `data/sample/`. Its output is written to `results_quick/`. Because the images are synthetic and train/validation/test point to the same tiny sample folder, these metrics are **not a valid held-out evaluation** and must not be quoted as the TrashNet test result.

## 7. Demo

After the full-dataset run has produced `models/waste_cnn.pth`:

```bash
streamlit run starter/app.py
```

Upload a JPG or PNG to view the predicted class, confidence, and class-probability chart. Images are resized and normalized identically to deterministic validation/test inference. Predictions below 50% confidence trigger a caution message. The model is limited to six TrashNet categories and is not disposal-safety advice.

## 8. Tests

```bash
pytest tests -q
```

The suite uses local synthetic images and temporary directories; it does not download TrashNet or train for 25 epochs. It tests model shape/configuration, training, checkpoint loading, prediction, image filtering, metric calculation, and the dataset split preparation utility. CUDA is optional; CPU execution is required.

## 9. Rebuild the Midterm slides

```bash
python scripts/build_presentation.py --team "Team name — member names"
```

The script reads the **current PyTorch** outputs from `results/`. If a full-dataset PyTorch run has not been completed, the slide deck explicitly marks full-data metrics as pending rather than displaying unsupported scores. Add the actual team and member names before submission; they are not inferred or invented.

- [ ] Run the complete experiment suite and confirm all reported model metrics identify `framework: pytorch`.
- [ ] Confirm the selected model was chosen by validation macro-F1, and test metrics are reported only for the selected CNN and baselines.
- [ ] Launch the Streamlit app with the generated `models/waste_cnn.pth` checkpoint and demo a test image.
- [ ] Rebuild `presentation.pdf`; confirm the team details, curves, test results and limitations match the generated PyTorch artifacts.

## 11. Scope and limitations

This repository version targets the **Midterm AI Core** only. The full TrashNet experiment cannot be reproduced until the dataset is downloaded. No full-dataset PyTorch score is claimed by the offline smoke test. The final submission should include the results generated by the documented PyTorch pipeline, not metrics from unrelated or historical runs.
